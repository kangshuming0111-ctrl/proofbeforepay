# ProofBeforePay：获奖作品对照与整改验收

评审日期：2026 年 11 月 2 日。范围：官方获奖公告、创作者公开资料、本项目源码及评测记录、DeepSeek 静态复核，以及本轮实际浏览器观察。本文不预测获奖概率，也不把其他比赛的冠军称为 PayPal 本届前届冠军。

## 判断

**项目已经具备完整的演示链条，但现有证据不足以宣称超过这些冠军。下一步最有价值的提升，是让买卖双方在同一处看懂“哪里没做到、修改了什么、AI 哪句可能有误、谁最终确认了哪一版”。** 这是产品核心，优先级高于增加炫酷界面或更多 Agent。

当前界面采用米白／绿色的紧凑三栏工作台，适合对照要求、交付和证据；本轮桌面观察没有支持整体改成赛博朋克风格的理由。真正的差距是证据连贯性、真实交付范围、双人使用验证及演示中的实际操作。

PayPal 官方对技术实现、设计、潜在影响、创新和呈现五项等权评分，要求 AI 与 PayPal 的实际作用。规则没有指定配色、动画或 Agent 数量。当前比赛尚未公布冠军。下面的优先级和验收门槛是我们的工程判断，并非官方附加要求。[PayPal 官方规则](https://paypalaihackathon.devpost.com/rules)

## 已有能力与不能越过的事实边界

本项目已记录一次同项目的 v1 → 修改请求 → v2 → 人工验收 → PayPal Sandbox 授权及独立扣款流程，刷新后状态保留，款项为 AUD 480 虚拟测试资金；卖家视角由同一持有人扮演。这证明有界演示链条，尚不证明两个独立账号的协作、真实卖家结算或托管服务。[评测与脱敏链条说明](EVALUATION-2026-11-02.md)

AI 评测保留了失败：原 19 例状态符合参考为 18/19，完整回答独立审查为 17/19；后续两版本评测为应用状态 14/14、原始模型状态 13/14，风险陈述有一条结构位置错误。后续小集不能覆盖原始失败，也不能推出生产准确率。公开评测资料已经存在，不能把 DeepSeek 未收到完整材料误判成“没有评测”。[完整方法、结果与限制](EVALUATION-2026-11-02.md)

现有 135 秒公开视频由真实界面截图编辑而成，适合审核状态，不能证明连续操作的流畅度。当前独立试用仍需要本地环境搭建，线上私有访问也不能写成公开可用体验。

## 与 DeepSeek 交叉复核后的整改顺序

| 门槛 | 需要完成的改进 | 通过的证据 |
| --- | --- | --- |
| **G1：先修判断一致性** | 中英文预约政策文案语义相同，却可能被中文“预约”关键词强制降为证据不足。本轮已复现并修复已声明的有限政策措辞；陌生表达仍保守弃权。Root 七例独立回归、另一审查者六十个受控探针及定向测试已通过，DeepSeek 最终源码复核未发现该范围内阻塞项。 | 成对中英文的等义／矛盾政策得到一致结果；“提交预约表单并收到邮件”等运行要求继续保守拒绝仅凭源码下结论；保存原始模型和应用处理后的两种状态。 |
| **G2：把争议解决做进产品** | 按同一验收项并排展示原要求、买家意见、v1／v2 原文与规则／浏览器／AI变化；为每条 AI 风险保存绑定版本的人工确认或驳回及理由，保留原始 AI 输出。 | 已知错误的“链接位于 main 外”风险可凭原文驳回，双方刷新后可见；新版本不继承旧版确认。用户能说明改了什么、仍缺什么证据；这些记录不自动触发验收或付款。 |
| **G3：能接收普通商家交付** | 支持有界的静态图片／CSS资源包、规范化相对路径和缺失资源检查。当前仅扁平 HTML／CSS 的范围有明确边界，但不能完整承接常见花店网站。 | 至少三个来源独立、许可清楚的真实风格静态包可提交和预览；图片与文件绑定准确版本；路径穿越、重名冲突及不支持的可执行格式被拒绝。脚本、表单和后台运行另需隔离验证，不通过放开预览脚本来冒充支持。 |
| **G4：验证两个真正参与者** | 定义明确的双账号 Sandbox 协作路径，买卖双方权限与测试收款方保持可解释。 | 两个独立认证账号完成同一项目，第三账号无法访问；卖家不能执行买家付款动作；收据绑定实际验收版本。明确标注虚拟付款，不声称真实卖家结算。线上访问调整另需持有人明确同意。 |
| **G5：证明连续体验** | 用当前版本正常操作录制关键连续片段；引入不熟悉项目的试用者。 | 三分钟内展示完整关键链条，真实等待、提交、返回和保存可见，剪辑如实标注；至少三名初次使用者尝试建项目、找矛盾、发修改和找收据，记录任务失败／耗时／误解，不编造用户认可或节省比例。 |

DeepSeek 提出的“优先项未排序”经独立源码检查不成立：`lib/delivery-overview.ts` 已排序，不能重复造一个优先级缺陷。其“评测缺失”来自审阅材料不完整，已排除。README 状态过时成立，根代理已调整文案，发布与最终核验仍以根代理结果为准。中英文差异成立，G1 的有界修复现已通过离线回归；没有据此宣称真实模型的所有中英文表达都已通过。接下来推进 G2，随后 G3／G4，最后用 G5 验证整个链条。

**可以努力做到比参照作品更清楚、更可信、更易复核；目前不能把这个目标写成已经胜过冠军的结论。** 下轮判断应看上述具体门槛是否留下了可重复检查的证据，而不是功能数量、调用次数或页面动效。
