# ProofBeforePay：获奖作品对照与整改验收

评审日期：2026 年 11 月 2 日。范围：官方获奖公告、创作者公开资料、本项目源码及评测记录、DeepSeek 静态复核，以及本轮实际浏览器观察。本文不预测获奖概率，也不把其他比赛的冠军称为 PayPal 本届前届冠军。

## 判断

**项目已把逐项证据对照、人工风险处置、本地图片交付和真实双账号 Sandbox 闭环落实到可操作产品，但现有证据不足以宣称超过这些冠军。下一步最有价值的提升，是证明不熟悉项目的人也能看懂“哪里没做到、修改了什么、AI 哪句可能有误、谁最终确认了哪一版”。** 三人首次使用测试和新的连续交互视频仍未完成。

当前界面采用米白／绿色的紧凑三栏工作台，适合对照要求、交付和证据；本轮桌面观察没有支持整体改成赛博朋克风格的理由。仍需加强独立首次体验、连续操作呈现，以及更广泛交付与权限边界的验证。

PayPal 官方对技术实现、设计、潜在影响、创新和呈现五项等权评分，要求 AI 与 PayPal 的实际作用。规则没有指定配色、动画或 Agent 数量。当前比赛尚未公布冠军。下面的优先级和验收门槛是我们的工程判断，并非官方附加要求。[PayPal 官方规则](https://paypalaihackathon.devpost.com/rules)

## 已有能力与不能越过的事实边界

本项目较早记录过一次同项目的 v1 → 修改请求 → v2 → 人工验收 → PayPal Sandbox 授权及独立扣款流程，刷新后状态保留，款项为 AUD 480 虚拟测试资金；卖家视角由同一持有人扮演。这份历史记录本身不证明双账号协作，仍单独保留。[评测与脱敏链条说明](EVALUATION-2026-11-02.md)

本轮另一个线上项目使用两个独立认证账号，卖家在 Safari 中实际加入、上传和提交。v1 有一项规则不符、三项 AI 修改建议，375 px 首页及服务页溢出 404 px；买家保存了一条 CSS 风险确认和四项退回意见。卖家整包替换并提交 v2，两版本各实际调用一次 DeepSeek，共两次新增调用，不并入较早的 31 次评测。v2 无规则不符或 AI 修改建议，但三条范围／coverage 风险被人工附理由驳回，原始报告保留。这不能写成 AI 全部陈述正确。

v2 六项页面／宽度观测均完成，无不可用结果、无水平溢出；买家另检查了三个页面的 375 px 显示、成功加载的 400 × 267 照片、实际 consultation 链接及等义政策文案，然后明确验收 v2，再单独批准、授权和扣款 AUD 1 虚拟资金。两端刷新仍显示 Test captured，收据绑定已验收 v2。**两个真实登录由同一开发者通过自动化代理操作，不算两名独立真人测试。** 收款方为配置的 Sandbox 测试商户，仍无实际卖家结算或托管服务。[本轮详细状态](../README.md#dated-follow-up-evidence-and-remaining-user-work)

AI 评测保留了失败：原 19 例状态符合参考为 18/19，完整回答独立审查为 17/19；后续两版本评测为应用状态 14/14、原始模型状态 13/14，风险陈述有一条结构位置错误。后续小集不能覆盖原始失败，也不能推出生产准确率。公开评测资料已经存在，不能把 DeepSeek 未收到完整材料误判成“没有评测”。[完整方法、结果与限制](EVALUATION-2026-11-02.md)

现有 135 秒公开视频由真实界面截图编辑而成，适合审核状态，不能证明连续操作的流畅度。当前独立试用仍需要本地环境搭建，线上私有访问也不能写成公开可用体验。

## 与 DeepSeek 交叉复核后的整改顺序

| 门槛 | 当前实现与实际验收 | 仍需保留的边界／后续门槛 |
| --- | --- | --- |
| **G1：先修判断一致性** | 中英文预约政策文案语义相同，却可能被中文“预约”关键词强制降为证据不足。本轮已复现并修复已声明的有限政策措辞；陌生表达仍保守弃权。Root 七例独立回归、另一审查者六十个受控探针及定向测试已通过，DeepSeek 最终源码复核未发现该范围内阻塞项。 | 成对中英文的等义／矛盾政策得到一致结果；“提交预约表单并收到邮件”等运行要求继续保守拒绝仅凭源码下结论；保存原始模型和应用处理后的两种状态。 |
| **G2：把争议解决做进产品** | 已实现同一验收项的原要求、买家意见、两版独立证据对照，以及绑定版本的追加式人工风险记录。本轮实际保存 v1 CSS 风险确认、四项修改意见、v2 三条风险驳回，原始 AI 报告保留。 | 处置不自动触发验收／付款；新版本不继承旧版确认。仍需陌生用户说明改了什么、缺什么证据；不能把较早“main 位置错误”记录写成本轮模型结果。 |
| **G3：能接收普通商家交付** | 已支持有界相对目录、HTML／CSS、本地 PNG/JPEG/WebP 和资源检查。本轮线上照片实际加载成功；三份不同许可来源包另有本地文件／交付校验记录。 | 不能把三份本地样例校验全称为线上浏览器通过。继续保留精确版本资源、路径与格式限制；脚本、表单、后台及图片像素理解仍不在本次源码 AI 验收范围。 |
| **G4：验证两个独立账号** | 已完成真实买家／卖家两个认证会话的加入、v1 提交、退回、v2 替换提交、人工验收及单独 Sandbox 授权／AUD 1 扣款；两端刷新仍 captured，收据绑定验收 v2。 | 两账号由同一开发者代理操作，不是独立用户研究。第三账号拒绝／卖家越权拒绝若仅有模拟集成证据，仍据实标明；不声称全部线上权限边界通过，也不声称卖家结算。 |
| **G5：证明连续体验** | 新英文录屏脚本和三人首次使用计划已准备；实际新连续录屏和独立参与者测试尚未完成。 | 三分钟内展示完整关键链条，真实等待、提交、返回和保存可见，剪辑如实标注；至少三名初次使用者尝试建项目、找矛盾、发修改和找收据，记录任务失败／耗时／误解，不编造用户认可或节省比例。 |

DeepSeek 提出的“优先项未排序”经独立源码检查不成立：`lib/delivery-overview.ts` 已排序，不能重复造一个优先级缺陷。其“评测缺失”来自审阅材料不完整，已排除。README 状态过时成立，现已按本轮流程补充。中英文差异成立，G1 的有界修复已通过离线回归；没有据此宣称真实模型的所有中英文表达都已通过。G2／G3 已实现并有上述有界线上验证，G4 的实际双账号闭环已完成；下一步重点是 G5，并补足未实际走查的更广边界。

**可以努力做到比参照作品更清楚、更可信、更易复核；目前不能把这个目标写成已经胜过冠军的结论。** 下轮判断应看上述具体门槛是否留下了可重复检查的证据，而不是功能数量、调用次数或页面动效。
