# 第 2 轮：双语价格与历史规则版本

- 日期：2026-11-07；起点为本目录第一轮冻结源码，尚未单独发布。
- 主差距：G91-INPUT-COVERAGE 的语言部分，以及第一轮明确保留的英文回退。
- 参照及证据层级：[PHAROS_INC 与 Agent Receipt 的官方获奖描述](https://www.bemyapp.com/insights/ai-builders-challenge-with-ibm-bob-2026-winners.html)，分别是 IBM Bob 2026 August Challenge 1st Place 与 Most Innovative。沿用规则一致性、可读报告及可回放证据维度；没有同条件竞品运行数据。

## 修改前与可检验门槛

旧中文价格句式能明确映射已锁定价格，英文同义有限句式却会暂缓；新增完整性门还使旧“两张约定菜单页的 Tea 价格”回放产生了真实降级。门槛是恢复这些已明确约定的完整价格表达，同时继续拒绝附加营业时间、条件语句、缺漏／重复／歧义菜名、错误币种或金额。

## DeepSeek 与独立裁定

两次有限计划审查分别覆盖英文和追加的中文金额表达。有效后审为 `outputs/noodle-four-fixes-2026-11-07/stage2-post-deepseek.json`，包含主要源码、导出／回放接缝及界面版本判断摘录；它不是外部功能测试。根代理检查后审中四个主要源码／测试哈希与当前文件完全相同，独立运行四套 36/36 测试。完整有限语法及兼容测试、类型检查、审查范围和冻结哈希另见 `stage2-final-adjudication.json` 与 `stage2-owned-source-freeze.json`。

## 实现与验证

新增 `bilingual-bounded-v2`，保留旧 `bounded-original-zh-v1` 函数体和历史语义。有限整句族支持原中文句式、英文明确菜名与 ISO 币种价格、中文“菜单中…的价格必须为…”及明确澳元／美元，还有恰好两张买家已锁定菜单页的价格原文。菜名按完整预期值消费，不把菜名里的 and 当成义务连接词；一个金额句不能借给不同币种／不同金额的锁定项目。

正常与模板路径通过真实 intake、业务计划与评估函数验证。附加条件继续未知，模型原本未知不被提升。导出和历史按每份报告自己的版本复算：同版历史 v1 英文未知与新 v2 支持可以并存，历史原件不变；伪装版本或删除新正向发布所需版本会被拒绝。原英文六项范围回放及 exported-tree 回放已通过原始 gold，没有改变原件、答案或核心比较规则。
