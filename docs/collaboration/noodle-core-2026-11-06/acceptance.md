# 面馆外包验收：固定完成条件

起点：c01044fb387918e649f547d37a9091164e9bc93f / v86。用户于本轮明确要求只完成面馆外包验收流程，按以下四项实际验证后结账；新增想法不得加入本轮完成标准。

## 固定范围与条件

| ID | 固定条件 | 可观察的完成门槛 |
| --- | --- | --- |
| F1 | 要求能判明白 | 菜品/价格及标签等源码要求的语义等价、实际错误、页面/字段错位分别有正确且可追溯的结论；仅源码不能证明的提交/保存保持未知并指出缺什么。原始模型答复、系统独立事实和人工确认分别保留。 |
| F2 | 歧义能处理完 | 双方分别明确确认同一条锁定要求对应的文件/表单；决定追加保存，重新打开仍在。单方、过期版本、改提案或错原文不能成为范围依据。映射不表示要求已满足。 |
| F3 | 修改能复检 | 卖家提交故障版、买家按要求反馈、卖家修订、重新检查同一条要求；旧版原报告和引文可查，新版不能沿用旧结论/验收。已确认范围在新版本须重新核对目标与证据后才能参与复检。 |
| F4 | 买家知道下一步 | 实际界面分别显示已证实的证据、不符、未知及下一位处理人/需要材料；从结果能打开对应要求、提出澄清/返工/补证、在新版复检，最后由买家明确决定验收。所有这些动作不自动付款。 |

## 同一固定场景的八个测试

使用虚构墨尔本面馆、原有双语菜单交付和新编写的联系表单文件。不含真实客户、合同、邮箱收件服务或实际资金。

1. 买家不加合同，确认中文自然需求：双语菜单的牛肉面价格 AUD18；联系表单含姓名和邮箱；提交结果能保存另需运行证据。
2. 正常源码与相同意义的布局/表格表达被正确识别，引用对应实际对象。不能要求没有约定的逐字句子。
3. 故障交付把 AUD18 写成 AUD28；识别同一菜品的价格差异。其他菜品或隐藏文字的正确价格不能借证通过。
4. 目标内容放错页面、字段或表单；不得把多个不相干位置拼成满足目标要求。
5. 只有表单源码而没有执行和独立回读；保存/邮件等运行能力保持未知，明确需要卖家补证，不伪造 bug 或成功。
6. 页面/表单别名有歧义；提出范围、双方分别确认、重新打开决定、按确认范围复检。单方/错角色/旧版本/改案均有失败对照。
7. 卖家上传修订版本；旧、新版同 criterion 可对照，旧报告未修改且不成为新证据；重新运行检查才产生新版结果。
8. 买家针对当前版提出修改、补证或明确人工决定；角色、版本和范围均有约束。验收与付款仍分别确认，本轮不执行金融动作。
