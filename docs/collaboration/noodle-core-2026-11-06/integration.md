# 面馆固定流程：集成审查与验证边界

本轮仅按 acceptance.md 中的 F1–F4 关闭流程。对奖项项目的对照仍限于官方公开描述：PHAROS_INC 的有限规则与清楚报告、Agent Receipt 的证据与权限关联、Vite Vere 的步骤引导。没有同条件跑竞品源码，不量化“超过冠军”。

## 本轮实际改动

- 模型原始逐项判断独立保留；系统对买家已锁定菜品/价格及完整 HTML 标签分组生成可重算的源码事实。原模型准确率与这层结果分开记录；源码关系不证明渲染、运行或持久化。
- 当前文件与明确 id 的表单构成候选。提案和确认分开，双方必须各自确认；旧版未确认提案不可继承。新提案立即取消旧提案的当前效力，但历史追加保存。
- 澄清变更会保留该版本旧 AI 报告，允许用新的范围重检。换版保留旧文件与原报告，但不继承当前评估或验收。作用范围映射在新文件中重新核对，不表示新交付通过。
- 买家界面分别展示系统事实、原始模型意见、人工确认、下一处理人及所需材料；确认范围后的“回到本项重新检查”只导航，不偷偷调用 AI、验收或付款。

## 独立判断与修复

DeepSeek 的计划、事后审查和最终窄审查分别由各 slice 记录，不将每条答复算一次整改。根集成第一次审查因引用未入包的 app/page.tsx 而无效，原答保留；更新精确页面摘录与六项真实函数测试后，integration-post-v2-deepseek.json 是有效静态审查，0 条有依据的缺陷。它没有替代下面的执行证据。

根独立审阅实际找出并修复两个异步边界：对方更新 scope history 后，GET 不应静默丢弃并停在加载态；response fence 用更新读取同步 quote 时，不得把之前响应的 scopeContext 再标成当前。tests/noodle-scope-page.test.ts 抽取实际页面函数、使用真实 quoteResponseFence 和延迟模拟，覆盖六条读写路径，未重复写入。

源码事实产生的返工草稿明确标为“独立源码事实”，不冒充原始 AI 说明；只读历史报告不提供返工、风险复核或执行动作。对应三个实际组件渲染/草稿测试保留在 tests/noodle-assessment-presentation.test.ts。

## 执行证据及界线

- tests/noodle-core-api-smoke.py：实际隔离 HTTP、全新迁移 D1，完成不加合同的需求、故障交付、范围提案、双方确认、改案、返工、修订、逐项明确验收；跨版本/角色/原文等负控，7 组通过。身份是两个 synthetic gateway actor，不是两个真实登录账号；业务观察输入是合成 fixture，真实浏览器行为另测。
- 两份源码仅用 UTF-16 原位置引文；表单保存边界仅在真实执行/独立回读证据存在时判断，静态表单不能被称为已保存或已送达邮件。
- F1 四个冻结虚构项目共九条语义参考，调用前剥离参考答案；第三个范围通过上述真实 HTTP 的两角色确认路径获得。首次 provider 原答保留，后续修复不覆盖。
- 完整回归、实际浏览器全流程、最终版本及 exact 公开源码的结果写在同目录 ignored outputs 的最终执行收据。本文不把待执行的现场检查提前标成完成，也不将历史双账号/付款测试重新计算为本轮新测试。
