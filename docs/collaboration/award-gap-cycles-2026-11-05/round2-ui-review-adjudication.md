The parent independently asked to reduce redundant interactions for unique candidates. The reducer now preselects only a valid-document field with `state === "candidate"` and exactly one candidate, as a preview. It does not write configuration or create a confirmation; those still require the seller's Confirm click. Ambiguous and unresolved fields are never preselected. The explanatory copy states this in Chinese and English. The real independent-fixture composition now takes exactly 13 Confirm actions, with no preliminary dropdown changes; every selector is asserted empty until its respective confirmation. A focused follow-up review is retained separately as `round2-ui-preview-review.json`.

The follow-up Harness turn completed, but its JSON omitted the required `limitations` field and was retained with `reportValid:false` / `invalid_report_schema`. This is a completed consultation attempt, not a protocol-valid review or a browser pass. Its raw advisory text was read independently:

- **Rejected alleged P2 cross-field handler corruption.** It asserts that field B's existing `onClick` begins dispatching field A's key after A is confirmed. In the supplied component, each callback closes over its own `field.key` and `chosen.id` inside `discovery.fields.map`. A reducer update cannot mutate those lexical bindings into another field's key, and a later render supplies another correctly scoped callback. Its claim that a disabled native button remains keyboard-activatable also does not match native disabled-button behavior. No executable counterexample or actual browser observation was provided. The real composed state test confirms all 13 unique previews separately; parent browser testing remains necessary for actual clicks, focus and rendering.
- **Not established as a user-visible defect: same-option select event revokes confirmation.** The reducer deliberately invalidates a confirmation on a `select` action. The suggested trace requires changing a native select to the exact value it already has, which does not produce the assumed ordinary value-change event. It provided no keyboard/browser reproduction. Retaining conservative invalidation for an explicit selection action does not create false confirmation or stale reports. No change was made on this unverified trace.
