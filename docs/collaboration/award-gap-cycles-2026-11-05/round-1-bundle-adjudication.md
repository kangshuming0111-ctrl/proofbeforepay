# 第1轮：离线模块观察与返工上下文裁定

本文件补充本轮主记录 `round-1.md`。对照维度是“技术检查是否推动具体用户行动，并留下可复核产出”，参照 Jayu 的 Best Overall App 和 PHAROS_INC 的分类第一名公开描述。没有检查这两个作品的内部实现，不声称它们执行过模块检验，也不据测试数判断整体优于冠军。

## 实际改进

- 保留统一包 schema v2 及旧 `pbp-supplemental-chain-v1` 规则。含 plan3 或新返工观察 `context` 的包明确使用 `pbp-supplemental-chain-v2`；创建与校验两侧都检查扩展与规则版本相符。旧规则不能悄悄承载新观察。
- plan3 重建使用当前包的真实 HTML、静态文件、精确 manifest 及 `analyzeModules:true`，核对 import map 等 HTML 上下文与计划一致。
- 原生校验核对模块观察与已保存文件摘要、路径、清单及有界读取关联；离线单独重算保存的依赖关系。包内不含原始 JS，所以没有离线重新运行 lexer、没有执行源码、没有按 import 发出网络请求。
- 公开查看器新增有名称的双语规则与模块关系核对项目，并显示有限模块诊断。关系核对失败时，界面保留失败说明，不显示重算为通过的结果；未知与漏声明继续显示。长诊断列表仅作有说明的展示截断，实际校验使用完整有界对象。

## 复查中新发现的真实缺陷

执行复现了 v61 的一个导出缺陷：对旧 v1 静态报告在新构建清单下产生的 `artifact_manifest_changed` 创建返工任务，离线导出只用默认 `artifactManifest:null` 重建问题，因此找不到该问题并报 `followup-bindings` 不一致。此前测试的任务引用其他诊断，未覆盖这个上下文相关分支。

本轮主代理为新任务冻结最小 `context:{artifactManifest}`，不包含任务头，避免递归膨胀；旧任务保持原字段和摘要。统一包收集每个原始／提议／历史事件引用的精确上下文 manifest，要求项目、交付及交付摘要一致，且 manifest 不能晚于相应事件。

新任务在更换清单与替换交付后，仍使用其原上下文重建问题。对旧无上下文任务，仅可复用包内已经原生重建成功的当前或冻结验收目录；没有保留的历史上下文仍明确拒绝，不借用无关清单补造事实。旧交付源码继续不在当前交付文件范围内。

## 验证与裁定

- `tests/evidence-module-bundle.test.ts`：10 项通过。含实际受控 Response 字节→模块观察→统一包；缺子模块不触发新请求；敏感外部引用不进入记录；动态表达式／import map 保持未知；规则降级、缺观察、篡改、字段重排、HTML 上下文、CLI／控制器零外网；旧上下文回退、新任务跨清单／交付、缺失历史及未来清单拒绝。
- `tests/evidence-viewer.test.ts` 新增两项，执行真实的核对项目与补充证据渲染函数。核实双语范围说明、漏模块诊断可见，以及关系校验失败时不显示已支持结果。
- 新旧 bundle、原 v1 导出、查看器合计 **53/53 通过**，TypeScript 零诊断。日志在 `outputs/award-gap-cycles-2026-11-05/bundle-module-focused.log` 和 `bundle-typecheck-final.log`。
- 生成了仅用受控响应的正反例：`bundle-module-valid.json` 一致，`bundle-module-missing-observation.json` 不一致。未外发真实 HTTP、调用模型或执行付款，包中不含原 JS 或私人 actor canary。
- DeepSeek 限定静态审查 `bundle-module-review-1.json` 协议有效、正常结束、findings 为空。它未执行测试，也未检查未提供的服务端读取、全部原生校验器、CSS、真实浏览器或竞品实现。实际测试证据独立于审查意见。
