# Round4: an independent concurrent-state experiment

The additional release-vs-transfer-v1 family is separate from the immutable twenty-step browser journey and the existing HTTP protocol checks. A uint32 seed chooses party size2–6 and a permutation of three slots. A fresh UUID namespace isolates each experiment. Three synthetic creates fill a target slot; cancellation of one target booking and transfer of a source booking are invoked concurrently. At most5 writes,24 HTTP requests and20seconds are allowed. The server saves each intent before I/O and checkpoints each completion. A failed checkpoint stops subsequent I/O; an unknown write is never resumed or replayed.

The pure oracle imports no seller implementation and reads no scenario/fault label. It compares all receipts, merchant rows, immutable creation keys/IDs and three occupancies against both legal serial orders, constrained by actual invocation/completion precedence. Matching one order is bounded compatibility, not a proof of all concurrency schedules or database honesty. Missing/timeout/non-JSON/oversized evidence is inconclusive. Reports retain the exact upload digest, operator-approved registration, model definition digest, seed and observed trace.

## Complete retained workflow

A durable thirty-second lease and32KiB reservation precede any target request. Current file hash, target registration and same-run CAS are rechecked on every checkpoint and completion, preserving concurrent human annotations. Only an explicit expired close can terminate an orphan; it issues zero target requests and retains unknown intents. Four reports per delivery are retained without silent eviction. Pending runtime/journey/model operations and payment operations mutually exclude new evidence/payment/replacement actions.

Acceptance requires the current explicit modelReportId (including null), exact model acknowledgement, and a10–500character reason for violated/inconclusive results. Frozen acceptanceA remains the payment basis after supplementalB. Historical snapshots are never backfilled. Replacement clears current model state but retains authorized version history. Model-agreement feedback names the exact current report separately from original contract criteria. Compact bilingual UI, saved-history and frozen-snapshot views expose these distinctions; offline exports independently rederive reports and validate references.

## Independent judgement of DeepSeek

Design advice to reuse or extend the old twenty-step report was rejected: it would change the meaning/digest of existing records and conflate browser claims with server-direct observations. Budget, exact digest binding and independent oracle advice were accepted. First implementation review returned a valid empty findings array with static-review limits.

Followup reviewed UI/snapshots and proposed five findings. The claimed missing exception-reason and acknowledgement carryover defects were rejected: report-ID reset, explicit reason gating and the parent's current-report decision guard prevent acceptance; remount creates new hook state. No successful acceptance without a required reason was reproduced. Its busy-flag claim contradicted the supplied unconditional finally release; rejected. The client-clock recovery observation was useful: the UI now permits one explicit close attempt and the server alone decides expiry, without retrying any target I/O. Accepted adding referenced/supplemental markers to model history rows. The claimed absent error signal contradicted the existing modelData.error warning; clarified that the entire invalid history set is withheld. Source review remains advisory and does not replace executed tests.

Independent review also found the first UI recovery request used a nonexistent route; changed it to GET/api/quotes/id before live publication. Busy release after unmount was checked explicitly. A focused second followup confirmed the original reason/reset/clock findings were addressed. Its claim that required invalidation on report replacement is itself a defect was rejected, but duplicate callback ownership was removed for clarity. Accepted a genuine consistency improvement: snapshot display now reads the same fully validated model history set as the run list, including duplicate-identity/run and four-report bounds. It no longer reads raw history independently after whole-set validation fails. Final static followup confirmed both targeted changes. It then suggested an altered-plan scenario which cannot currently occur: the technical recipe has one immutable digest, and replacement clears the current reports. The UI has no project ID prop, so no invented project identifier was added; authenticated server/offline validators retain the project binding. See round-4-domain.md for domain validation detail.
