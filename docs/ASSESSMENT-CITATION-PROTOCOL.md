# Source assessment citations and relationship scope

The active `assessDelivery` route requests `submit_source_assessment_v3` with DeepSeek's strict named tool output. It accepts exactly one matching tool call. Content-only JSON, the old named function, mixed selectors, unknown selectors, duplicate selectors in one citation list, or another catalog identity are rejected without a fallback request or automatic retry.

`createAssessmentCitationCatalog` snapshots every validated HTML/CSS source file and pure JSON delivery/scope binding. Complete fixed windows cover the source without normalization or truncation; short original semantic element spans are added as alternative addresses. Each catalog identity hashes the version, full source, binding and entries. A selector names one exact file and UTF-16 start/end occurrence, so identical text in another location is not interchangeable. The server restores the original excerpt directly from the frozen entry. It never searches for a model-rewritten quote or chooses the nearest selector.

The catalog has 1536-entry and 384-KiB serialized limits; the complete request retains its 850000-byte admission ceiling. A full catalog that cannot fit is rejected before model I/O, rather than hiding late source. Provider arguments remain capped at 30000 UTF-16 units, and an equivalent expanded report is separately capped at 30000. Limits are engineering admission bounds, not a provider capacity guarantee. Item citations remain six, risk citations three, with all required criterion and risk fields checked.

The saved `ProofAssessment` shape stays `source-ai-v1`: that version identifies the saved advisory schema, not the wire protocol. A fixed system limitation records catalog protocol and catalog identity. Saved exact file/start/end/excerpt evidence and existing export validation continue to work. Evaluation artifacts separately retain the original tool arguments, selected IDs, frozen catalog, actual encoding and restored spans; a restored quote is not represented as model-authored text. Original JSON validity and the narrow one-trailing-brace compatibility are recorded separately.

`assessDeliveryLegacyReplay` is an explicit historical fixture entry point. Production routes do not invoke it. Historical quote-format tests name this entry point; active-route, catalog and current evaluator tests exercise the active V3 slot protocol; separately named fixtures retain V2. Historical reports remain readable, without allowing an active model response to choose the old wire format.

A valid selector proves source provenance only. For buyer-confirmed business checks, a supported item must also cite a complete, server-located owner in each specified file. Another page with the same string, an adjacent product with the same price, a heading, or only part of the locked checklist cannot substitute. The guard can withhold supported advice as insufficient evidence; it never upgrades unknown or changes advice. Existing definite mismatches retain their precise source evidence. Multiple fragments that jointly cover an owner, without one complete owner span, remain conservatively unknown.

The recognizer supports deliberately bounded source structures, rather than arbitrary visual or runtime relationships. Unsupported structures, ambiguous or repeated labels, dynamic alternatives and unsupported source dependencies retain uncertainty. It does not infer currencies from `$`, guess a file from a generic page name, turn source text into a browser observation, establish comprehensive security, accept work or initiate payment. General prose entailment and conclusions beyond the confirmed checks still require independent review.

Current batch records and per-cycle award comparisons: [citation-relations-2026-11-05](collaboration/citation-relations-2026-11-05/).

The follow-up universal-tag witness recognises two finite source-content grammars and requires explicit HTML filenames. For each file, the unique literal item name, tag and optional same-symbol price must occur within the nearest bounded original block, and the model must cite that complete block. A tag on an adjacent item or grandparent does not substitute. Natural-language page-role aliases remain unknown: a two-file required list is not a trusted mapping from roles to filenames. The witness is negative-only and does not establish all semantics, visibility or nutrition. Complete small `div/span/input/h2/h3/td/th` addresses assist citation selection without changing what they prove.

The static relationship scope descriptor permits explicit source-only HTML `for/id`, input `type`, and radio `name/value/label` statements to receive source advice. It recognises complete finite syntax, with runtime, visibility, security, financial and record clauses still vetoed. Scope admission is separate from checking whether the property is actually correct; raw unknown advice is never promoted by admission alone.

The active V3 wire now uses fixed citation slot objects (`c1..c6` for an item, `c1..c3` for a risk), all required with no extra fields. Slots contain exact catalog IDs and only unused trailing slots use `""`. The schema expresses the maximum without unsupported array cardinality keywords; local checks still reject omissions, extras, gaps, duplicate or unknown IDs. `assessDeliveryCatalogReplay` explicitly retains V2-array fixtures, while `assessDeliveryLegacyReplay` retains old quotation fixtures. Neither is a live fallback. Raw slots are retained separately from the normalized selector view used for coverage and from server-restored saved excerpts.

A linked business plan whose source association remains unknown also withholds an unsupported model change allegation. A definite located mismatch retains its existing path, and authoritative server failures remain prior to these advisory guards. This does not convert ambiguous source into an actual defect.

## Active V3 publication policy

Publication handling applies only to active `catalog_slots` V3. Explicit V2 catalog-array and legacy-quotation replay entry points retain their historical publication behavior; neither is a live fallback. All item/risk fields, criterion coverage, exact citations and expanded-output budgets are validated before publication. Withholding cannot repair malformed risks, invent a suggestion or admit an invalid response.

Model limitation prose is text-validated but not published as verified fact. Only its count reaches the publication policy, which adds a fixed withholding note. Deterministic system notes count actual supplied HTML/CSS/raster files using the production type classifier and state that this source assessment did not run a browser, scripts or backend, or analyze pixels. Source script strings do not prove execution; excluded raster input does not mean a delivery asset is missing.

If any final item status differs from the model status, all optional model risks are temporarily withheld with explicit adjustment/risk counts. Citation/file overlap is not a trustworthy semantic dependency map. This deliberately coarse gate can withhold useful unrelated leads; it does not establish that their issues are false or resolved. Individual statuses and reasons remain available. With no status changes, validated risk copies remain AI leads awaiting human review.

The initial cycle-15 publication implementation did not add structured original-risk or adjustment-history fields to live reports. Those historical reports are not backfilled. Cycles 17–18 now retain the validated original withheld leads and adjustment bindings described below; this does not imply that historical live reports or every current report retain the full provider response envelope. Benchmark transport artifacts and previous application reports are a separate audit layer. Publication does not accept work, authorize or move money.

The final controlled replay reused15 retained provider bodies with byte-identical requests and zero new model/network calls. Its82 statuses and input project-quote hashes stayed unchanged; report explanations and citation sets could change. Three canonical mismatch consolidations reduced item citations180→174; six withheld risk rows reduced risk citations63→48. Retained originals therefore contain243 exact quotes and the current replay publishes222. These are separate audit layers.

Clean Blog requires a370-UTF-16-unit raw text interval per page, below the500-unit quote limit. Four appropriately addressed quotes could fit within six slots. Current frozen catalog/selected evidence does not cover the whole requirement; this is a granularity/selection limitation, not an intrinsic six-slot impossibility.

## Structured review guidance and retained withheld leads

Cycle 16 adds optional `evidenceNeed` to active V3 items whose final status is `insufficient_evidence`. Its exact schema is `source-evidence-need-v1`, a finite twelve-code reason and at most 40 deduplicated exact provided HTML/CSS target keys. A server guard records its actual branch; unexplained model uncertainty uses `model_unresolved`, never a reason inferred from model prose. Empty targets do not assert that no evidence is needed. Shared bilingual UI/draft wording preserves the full recorded target list, while the existing 1,000-UTF-16-unit editable draft explicitly labels source/explanation excerpts and any omitted full file list. Record-readback guidance conditionally asks for separate email or other execution evidence when the same locked requirement also includes it. It does not add scope or execute an operation.

Every new active V3 report has `withheldRisks: {version: 1, reason, adjustedCriteria, entries}`. `reason: "not_withheld"` requires two empty arrays and leaves validated published leads available. `reason: "item_status_adjusted"` requires nonempty exact criterion/model-status/published-status adjustments and no published risks; zero to five entries retain each `originalRiskIndex` and the validated original risk's title, explanation, suggestion and source citations. The model's raw transport envelope is not part of this saved extension. Existing mandatory response validation runs first; neither this pool nor publication withholding repairs bad risk fields or citations.

Cycle 18 permits append-only human opinions in the retained pool using the sole explicit `riskOrigin: "withheld"`. An absent origin keeps the legacy published-lead meaning; it is not a second spelling of withheld. Delivery, assessment, origin, original index and actor role bind current and historical records separately. Published summaries exclude withheld opinions. A human opinion cannot release the publication gate, edit original AI findings, mark a repair, accept work or trigger payment; the withheld section has no linked repair action.

Missing historical metadata is not reconstructed from count notes. Current and historical exports validate the new optional structures and exact bindings; malformed extensions fail closed. The CLI and Lab must use the updated native verifier before checking a new-format export. An offline consistency result proves neither the asserted cause/original model status nor model execution, human identity or runtime behavior. The [review guidance](ASSESSMENT-REVIEW-GUIDANCE.md) lists all twelve reasons, participant actions, draft limits and verifier instructions. These source changes do not by themselves establish a particular hosted deployment version or a new live evaluation result.
